# 限时数据分析任务：应战设计（需求对齐定稿）

日期：2026-10-21
状态：已与用户对齐；任务尚未开始，数据未发放。

## 1. 目标

在 30 分钟（+5 分钟宽限）内，从任务方发放的一份 CSV 中找出一个真实的业务根问题，用可复现的数字与图证明它，并把公开 GitHub 仓库地址提交到任务页面。

评分看的是判断与证据链，不是模型复杂度或图表数量。

## 2. 硬约束（来自任务规则）

- 计时以服务器时间为准，刷新/换设备不重置；到点后 5 分钟内提交不算迟交。
- 交付一个**公开** GitHub 仓库地址；仓根必须有 `README.md` 与 `AI_LOG.md`。
- README 必须写清：我的判断（看到了什么、根问题是什么）、做了什么、怎么证明有用。
- README 引用的**每个数字**都必须能由发放的数据算出，并提供可复现脚本或步骤，评审会逐条核对。
- AI_LOG 记录关键 AI 交互：提示词、AI 哪里不对、怎么改的；审查子 agent 的工作也并入。
- 只能使用发放的数据；自造数据必须标明，且不能作为结论依据。
- 开始后可多次提交；评分以时限内（含宽限）最后一次提交为准。

## 3. 分工（用户已明确）

AI 负责整条链：下载后的读文件 → 体检 → 出数出图 → 写 README/AI_LOG → commit/push。

用户只在三个节点拍板：
1. 任务开始前确认应战方案（已完成）；
2. 推送前看结果；
3. 在任务页面提交仓库地址。

开始瞬间只有用户能做：点「开始」、下载 CSV、把任务书原文与文件路径给 AI。

## 5. 交付契约

仓库结构：

```
README.md                 判断 / 做了什么 / 怎么证明 / 复现命令
AI_LOG.md                 真实交互、AI 错误与修正、审查记录
run_all.py                一键入口：--data <csv> --out results
analysis/                 读取、列映射、体检、口径、导出
data/                     正式任务数据（原样提交）
results/results.json      机器可读结果；README 只引用这里
results/summary.md        体检摘要
results/figures/          结论图
tests/                    合成数据回归测试，与结论无关
```

数字纪律：

- README 不手抄终端输出，只引用 `results.json` 的字段；
- 每条结论后标注支撑它的字段/图，不把分组差异写成因果；
- 任何剔除、去重、退货处理都必须先在 README 声明口径；
- 图表只保留支撑根问题的 2–3 张，轴从 0 起，标题写口径与样本量。

## 6. 已落地的口径层

`analysis/policy.py` 枚举三类选择并各算 totals：

- 去重：不去重 / 整行相同去重 / 同订单号去重；
- 退货：计入（含退货毛额）/ 剔除所有退货行 / 净额（剔除退货正单，保留负冲减）；
- 金额：原始销售额 / 单价×数量（无法重算时回退并计数）。

默认口径：整行去重、退货计入、金额取原始值；摘要与图都按默认口径过滤后的数据生成，`reconciliation` 校验分组加总等于 `default_totals`。

体检层（`analysis/quality.py`）只报事实与影响金额，不做剔除；异常示例带订单号与日期，便于回查。

读取层（`analysis/io_utils.py`、`schema.py`）不依赖固定列名：编码按可解码性判断，分隔符嗅探，列名同义词映射；映射歧义与 “Unit Cost” 类风险显式标记。
